# Handoff: M1 — MVP, Bukhari + Muslim

*Brief for the session that picks up M1. Read `docs/STATUS.md` first, then this file.
The design is in `docs/PROPOSAL.md` §4–5; this brief only adds what M0 learned and
turns it into concrete steps.*

## Goal and exit criteria (from PROPOSAL §5.6)

1. Within-book and cross-book merge of **Bukhari + Muslim** into merged hadith (`U6-xxxx`).
2. Gold set built and evaluated; **≥ 97 % precision on `same`** (the quality gate).
3. A **30-page sample PDF**, both editions (A by attestation, B by topic), English + Arabic,
   for the owner to review the format.

Counts: Bukhari 7,589 records (7,580 non-empty); Muslim 7,563 (7,360 non-empty). Muslim's
Muqaddima (`intro: true`, entries 1–92) is almost absent upstream: only 3 of 92 have text.
Muslim has **667 `ref`** and **717 `ref_variant`** entries.

## What M0 learned that changes the plan

1. **Back-references are free edges.** A `ref` record ("بهذا الإسناد مثله") is the same
   hadith as the preceding non-ref record in the same chapter: add a `same` edge with
   `source="backref"`, no matcher needed. A `ref_variant` gets a `partial`-or-`same` edge
   to its predecessor *and* its own fragment is matched normally (it may carry an addition
   that matters for italics). Guard: only link within the same `chapter`.
2. **Muslim's FAB numbering is a near-gold within-book clustering.** Fuad Abd al-Baqi
   gives one base number to a hadith and its supporting chains (`8a`, `8b`, …): 2,963 bases
   cover the non-empty Muslim records, 1,860 of them with several members. Use it
   (a) to seed and sanity-check the gold set, (b) to measure within-Muslim recall.
   Do **not** treat it as truth: some sub-letters are related-but-different reports.
3. **Split errors are ~10 %** (see `docs/reports/m0-split-eval.md`). Use containment-style
   features (Jaccard **and** containment of char 5-grams) so a few chain words leaking into
   the matn do not block a match. When a pair is borderline, also compare the full `text`.
4. **No embedding model can be downloaded** (huggingface.co is blocked by the network
   policy). Unless the owner allows it, the second candidate channel is **TF-IDF over char
   3–5-grams with sparse cosine kNN** (scikit-learn, from PyPI, which works). MinHash-LSH
   stays the first channel (`datasketch` installs from PyPI).
5. **`ANTHROPIC_API_KEY` is not set** in the environment. Everything up to the middle band
   (steps 1–4 below) can run without it. Check with
   `env | grep -c ANTHROPIC_API_KEY` (never print the value) before step 5.
6. Typst is available from PyPI (`pip install typst`, Python bindings, v0.15). No system
   install needed.

## Steps

Each step writes to `data/m1/` (create it), is idempotent, and is committed and pushed
when it finishes (PROPOSAL §5.5). Suggested module names in brackets.

| # | Step | Output | Notes |
|---|---|---|---|
| 1 | **Matching table** [`u6/match_text.py`] | `data/m1/match.jsonl` | one row per non-empty, non-intro record: id, kind, match text, char-5-gram count. |
| 2 | **Free edges** [`u6/edges.py`] | `data/m1/edges.jsonl` | exact-hash `same`; backref `same`/`partial`. Every edge records `source` and `score`. |
| 3 | **Candidates** [`u6/candidates.py`] | `data/m1/candidates.jsonl` | MinHash-LSH (char 5-grams, 128 perms) ∪ TF-IDF kNN (k = 10). Within- and cross-book. Expect tens of thousands of pairs, not millions. |
| 4 | **Features + auto-decide** [`u6/features.py`] | add `features`, `auto_label` | Jaccard, containment both ways, length ratio, TF-IDF cosine, same-Companion flag (`isnad_last`), same-FAB-base flag. Thresholds are **calibrated on the gold set** (step 6) — start with placeholders and leave the middle band undecided. |
| 5 | **Gold set** [`u6/gold.py`] | `data/m1/gold.jsonl` | ~300 pairs stratified by score band + ~50 hard negatives (same chapter, different hadith). Annotated by Sonnet, then **verified by the owner** (export a side-by-side HTML/Markdown sheet). Labels: `same` · `partial(A⊂B)` · `related` · `different`. |
| 6 | **Calibrate + evaluate** [`u6/evaluate.py`] | `docs/reports/m1-eval.md` | Precision/recall for `same` and `partial`; choose thresholds that hit ≥ 97 % `same` precision on gold. |
| 7 | **Middle band → LLM** [`u6/llm_batch.py`] | `data/batches.json`, `data/m1/llm_labels.jsonl` | Message Batches API, Haiku (`claude-haiku-5-5`), 25–50 pairs per request, structured JSON output with confidence. Low confidence or disagreement with lexical signals → Sonnet (`claude-sonnet-5-5`). Hard spend cap in config; log actual cost. Record batch IDs so a later session can collect results. |
| 8 | **Clustering** [`u6/cluster.py`] | `data/m1/hadith.jsonl` | connected components on `same`/`partial` edges + anti-chaining guard (split a cluster when its farthest members fall below a similarity floor; send those to review). Sanity: every narration ID is in exactly one hadith; Bukhari ≈ 2,600 unique, Muslim ≈ 3,000 unique. |
| 9 | **Representative, alignment, stars** [`u6/assemble.py`] | fields in `hadith.jsonl` | fullest version, tie-break B → M; clause-level alignment for roman/italic; ★ count over the six (only B, M in M1), 🟢/🔵 badges. Uncertain alignment → no italics. |
| 10 | **Sample PDF** [`typeset/` + `u6/export_typst.py`] | `out/m1-sample-*.pdf` (not committed if large; attach to a GitHub release or share as files) | 30 pages, both editions, EN + AR. English for the sample only: translate the ~60 sampled representatives with Sonnet, labelled "machine translation (draft)". Arabic font must be free (e.g. Amiri or Noto Naskh Arabic from Google Fonts / PyPI-free source; check the font licence). |

## Budget for M1

From PROPOSAL §5.3, the M1 share is small: gold annotation (~350 pairs, Sonnet) +
Bukhari/Muslim middle band (~8–10k pairs, Haiku) + escalations + sample translation is on
the order of **$5–10**. Set the stage cap at **$15** and stop for the owner if it would be
exceeded.

## Decisions already made (don't reopen)

- Unit of deduplication = same matn, regardless of isnad/Companion (PROPOSAL §4.1).
- Precision over recall: a false merge hides a hadith.
- No modern grader; no upstream English text; no third-party grades.
- Bulk LLM work through the Batch API, not subagents.

## Pitfalls seen in the data

- Muslim entries `1–92` (Muqaddima) are mostly empty upstream; 344 Muslim records have no FAB number.
- Upstream marks many entries' chapter as 0 and points some empty placeholders into other books; M0 fixes `chapter` (see `data/README.md`). A handful of Tirmidhi/Ibn Majah entries sit out of chapter order upstream; keep source order (`seq`) as the canonical in-book order.
- Fractional numbers (`bukhari:402.2`) are upstream sub-entries; their sunnah.com URL is unknown, so the concordance leaves it blank.
- Some Bukhari entries contain two hadiths in one record (e.g. 622, 1121). Expect a record to belong to two clusters in rare cases; allow `member.role = "contains"` rather than forcing one cluster.
- Bukhari *mu'allaq* entries (`وقال الليث …`) have short or no chains (`split_flags` contains `no_isnad` for 11 of them).
