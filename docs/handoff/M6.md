# Handoff: M6 — website

*Brief for the session that builds the website. Read `docs/STATUS.md` first (including the
security section), then this file, then `data/release/README` notes in `src/u6/m5.py`
(`DATASET_README`) for the data schema.*

## Goal

A free, static, searchable website for The Unified Six on **GitHub Pages** (PROPOSAL §3.4):
every one of the 13,003 hadith gets a permanent page; readers can browse by topic and by
attestation, search English and Arabic, and click a hadith to see its sources, chains,
variants and Companions. Built from the same data as the PDFs; no server, no database.

## Budget and constraints

- **API spend: $0.** The API credit is used up; nothing here needs an LLM.
- **Hosting: free** — GitHub Pages (public repo; 1 GB site limit, 100 MB per file, ~10 builds/hour).
- **No secrets** in the site or its workflow. No analytics or third-party trackers.
- The repository is public and was attacked once (see STATUS → Security). Keep third-party
  code to a minimum and pin every version.

Regenerate the inputs with `python -m u6 m5 clean && python -m u6 m5 dataset` (no API).

## Recommended design

**Generator:** a Python module `src/u6/site.py` (stage `python -m u6 m6 build`) writing plain
HTML/CSS into `site/` (gitignored) — no framework, no client-side app. Jinja2 is acceptable if
pinned; f-strings are enough.

**Pages**

| path | content |
|---|---|
| `/` | what this is, how to read an entry, disclaimers (machine grouping, machine translation, stars ≠ authenticity), links to editions, PDFs (GitHub Release) and dataset |
| `/topics/` and `/topics/<slug>/` | the 33 topics; each lists its hadith ★6 → ★1 (Edition B order) |
| `/stars/<n>/` | ★6 … ★1 (Edition A order), paginated (★1 has ~7,700 entries: ~200 per page) |
| `/h/<U6-id>/` | **one page per hadith** (below) |
| `/books/<book>/` | per-book index: book number → hadith (from the concordance), so `/books/bukhari/1/` finds "Actions are by intentions" |
| `/about/` | method, numbers from `docs/reports/*`, license (CC BY 4.0 text/data, MIT code), changelog |

**Hadith page** (the interactive part — use `<details>` and a few lines of vanilla JS, no framework)
- English (roman = in every full version, *italic* = only in some) and Arabic (`lang="ar" dir="rtl"`, Amiri), side by side on wide screens, stacked on phones.
- Bracket: stars, muttafaq / one-Ṣaḥīḥ badge, book letters, al-Tirmidhī's grade, ≈ for uncertain grouping, both edition numbers.
- **Sources** (expandable): every member narration — book, number (Muslim: FAB number), full/fragment, chain-only, narrator, sunnah.com link, Tirmidhi grade; the representative marked.
- **Variants:** hovering/tapping an italic clause highlights which narrations carry it (`segments[].in`).
- **Chains:** expandable full Arabic text of each member narration (from `data/narrations`).
- "See also" links, topics (primary + secondary), "corrected in v1.1" note when `review_fix` is set, machine-translation label, and a **Report an issue** link (same prefilled GitHub issue URL as the PDFs: `.../issues/new?title=<id>%3A%20`).
- Omit segments from `commentary_from` on (al-Tirmidhī's commentary) in the main text, as the PDFs do.

**Search:** [Pagefind](https://pagefind.app) run after the build (`npx pagefind@1.3.0 --site site`
— pin the version). Static index, loads in chunks, works on GitHub Pages. Index the English and
the Arabic (`data-pagefind-body` on the text blocks; Arabic block with `lang="ar"`); filters via
`data-pagefind-filter` for topic, stars, books, badge. Check Arabic search quality on a few
words (with and without diacritics — consider indexing a diacritic-free copy of the Arabic,
hidden, using `u6.textnorm.letters`).

**Look:** readable serif for English, Amiri for Arabic, generous line height, light and dark
mode (`prefers-color-scheme`), mobile first, no horizontal scroll. Respectful and plain — no
decorative imagery.

**Deploy:** `.github/workflows/pages.yml` — on push to `main` (and manual run): checkout,
setup-python, `pip install -e .`, `python -m u6 m5 clean && python -m u6 m5 dataset &&
python -m u6 m6 build`, `npx pagefind@1.3.0 --site site`, then `actions/upload-pages-artifact`
+ `actions/deploy-pages`. Permissions: `contents: read`, `pages: write`, `id-token: write` only.
Pin action major versions as the release workflow does.

**Owner step (once):** repo **Settings → Pages → Build and deployment → Source: GitHub Actions**.
The site then lives at `https://taksir.github.io/The-unified-six/` — every link must be
relative or use that base path.

## Size and speed (estimates — measure)

13,003 hadith pages at ~5–10 KB ≈ 65–130 MB; listing pages small; Pagefind index ≈ 20–50 MB
in chunks. Well under the 1 GB limit. Build: a few minutes on Actions.

## Work plan

1. `site.py` with the hadith page only; build 50 pages; check them in a browser (Playwright is
   available in cloud sessions — screenshot desktop and phone widths, light and dark).
2. Listing pages, book index, home/about.
3. Pagefind; test English and Arabic queries.
4. `pages.yml`; owner switches Pages to "GitHub Actions"; first deploy; check links.
5. Tests: a small `tests/test_site.py` (page count, every member narration linked once,
   no `no_text` entries, commentary cut applied, relative links resolve).
6. Update `README.md` (site link), `docs/STATUS.md`, and write `docs/reports/m6.md`.

## Exit criteria

- Site live on GitHub Pages; every hadith reachable by permalink, topic, star level and book number.
- Search works for English and Arabic.
- Sources/variants/chains expand on every hadith page; report-an-issue links work.
- Passes a phone-width check; works in dark mode; no console errors.
- Rebuilt automatically on every push to `main`.

## Rules carried over

- Commit and push at the end of every stage; update STATUS.
